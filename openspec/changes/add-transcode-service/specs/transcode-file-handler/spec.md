# Transcode File Handler 规范

## 1. 概述

本规范定义了转码服务的文件处理机制，用于处理本地共享存储文件和远程 HTTP 地址两种输入方式。文件处理模块负责文件的获取、临时存储、缓存管理和清理，确保转码过程能够高效、安全地访问输入文件。

## 2. 功能需求

### 2.1 输入源类型
- **本地共享存储文件**：直接访问本地文件系统中的文件
- **远程 HTTP 地址**：通过 HTTP/HTTPS 协议下载远程文件

### 2.2 文件获取
- **本地文件**：直接读取本地文件系统路径
- **远程文件**：通过 HTTP 客户端下载远程文件
- **文件验证**：验证文件是否存在、可读、格式正确
- **文件大小检查**：检查文件大小是否在允许范围内

### 2.3 临时文件管理
- **临时目录**：配置临时文件存储目录
- **文件命名**：使用唯一标识符命名临时文件
- **文件权限**：设置适当的文件权限
- **文件清理**：转码完成后自动清理临时文件

### 2.4 文件缓存
- **缓存策略**：支持基于 URL 和文件哈希的缓存
- **缓存过期**：配置缓存过期时间
- **缓存清理**：定期清理过期缓存
- **缓存大小限制**：限制缓存目录的最大大小

### 2.5 文件类型检测
- **文件扩展名检测**：基于文件扩展名判断文件类型
- **文件头检测**：通过文件头信息判断文件类型
- **MIME 类型识别**：识别文件的 MIME 类型
- **支持的格式**：视频（MP4、AVI、MKV、MOV 等）、音频（MP3、AAC、FLAC 等）

### 2.6 文件路径解析
- **变量替换**：支持路径中的变量替换（如 ?tenant、?year、?month、?day、?task_id）
- **路径规范化**：规范化文件路径格式
- **路径验证**：验证路径的合法性和安全性
- **相对路径处理**：支持相对路径和绝对路径

### 2.7 并发控制
- **文件锁**：防止多个任务同时处理同一文件
- **下载限速**：限制文件下载速度，避免占用过多带宽
- **并发下载**：支持多个文件的并发下载
- **重试机制**：下载失败时自动重试

## 3. 非功能需求

### 3.1 性能
- 文件下载速度：至少 10MB/s
- 文件缓存命中率：> 80%
- 临时文件清理延迟：< 1s

### 3.2 可靠性
- 文件下载失败重试：最多 3 次
- 临时文件清理：100% 成功率
- 文件验证：100% 准确率

### 3.3 安全性
- 路径遍历防护：防止路径遍历攻击
- 文件大小限制：防止大文件攻击
- URL 验证：验证 URL 的合法性
- 文件权限控制：确保文件访问安全

### 3.4 可扩展性
- 支持新增输入源类型
- 支持新增文件类型
- 支持自定义缓存策略

## 4. 数据模型

### 4.1 数据库表

#### 4.1.1 transcode_file_cache 表
| 字段名 | 数据类型 | 约束 | 描述 |
|-------|---------|------|------|
| id | VARCHAR(36) | PRIMARY KEY | 缓存ID |
| source_url | VARCHAR(500) | NOT NULL | 源文件URL或路径 |
| file_hash | VARCHAR(64) | NOT NULL | 文件哈希值 |
| file_size | BIGINT | NOT NULL | 文件大小（字节） |
| file_type | VARCHAR(20) | NOT NULL | 文件类型（VIDEO、AUDIO） |
| cache_path | VARCHAR(500) | NOT NULL | 缓存文件路径 |
| status | VARCHAR(20) | NOT NULL | 缓存状态（DOWNLOADING、COMPLETED、EXPIRED） |
| created_at | DATETIME | NOT NULL | 创建时间 |
| expires_at | DATETIME | NOT NULL | 过期时间 |
| last_accessed_at | DATETIME | NOT NULL | 最后访问时间 |
| access_count | INT | NOT NULL DEFAULT 0 | 访问次数 |

### 4.2 Redis 数据结构

#### 4.2.1 文件锁
- **名称**：`transcode:file:lock:{fileHash}`
- **类型**：Redis String（用于分布式锁）
- **结构**：存储锁的持有者信息和过期时间

#### 4.2.2 下载队列
- **名称**：`transcode:download:queue`
- **类型**：Redis List 或 Redisson RBlockingQueue
- **结构**：存储待下载的文件信息

## 5. API 接口

### 5.1 文件处理接口

#### 5.1.1 获取文件
- **路径**：`/api/transcode/file/get`
- **方法**：POST
- **请求体**：
  ```json
  {
    "source": {
      "type": "local",
      "path": "/path/to/file.mp4"
    }
  }
  ```
  或
  ```json
  {
    "source": {
      "type": "remote",
      "url": "http://example.com/file.mp4"
    }
  }
  ```
- **响应**：
  ```json
  {
    "fileId": "string",
    "filePath": "/tmp/cache/file.mp4",
    "fileSize": 1024000,
    "fileType": "VIDEO",
    "status": "READY"
  }
  ```

#### 5.1.2 释放文件
- **路径**：`/api/transcode/file/release/{fileId}`
- **方法**：DELETE
- **响应**：
  ```json
  {
    "fileId": "string",
    "status": "RELEASED"
  }
  ```

#### 5.1.3 查询文件缓存
- **路径**：`/api/transcode/file/cache`
- **方法**：GET
- **参数**：
  - `sourceUrl`：源文件URL或路径
  - `page`：页码（默认1）
  - `size`：每页数量（默认10）
- **响应**：
  ```json
  {
    "total": 100,
    "page": 1,
    "size": 10,
    "items": [
      {
        "id": "string",
        "sourceUrl": "string",
        "fileHash": "string",
        "fileSize": 1024000,
        "fileType": "VIDEO",
        "cachePath": "/tmp/cache/file.mp4",
        "status": "COMPLETED",
        "createdAt": "timestamp",
        "expiresAt": "timestamp",
        "lastAccessedAt": "timestamp",
        "accessCount": 10
      }
    ]
  }
  ```

#### 5.1.4 清理过期缓存
- **路径**：`/api/transcode/file/cache/cleanup`
- **方法**：POST
- **响应**：
  ```json
  {
    "cleanedCount": 50,
    "cleanedSize": 512000000,
    "cleanedAt": "timestamp"
  }
  ```

## 6. 实现方案

### 6.1 技术选型
- **HTTP 客户端**：Spring WebClient
- **文件缓存**：本地文件系统 + Redis 元数据
- **文件锁**：Redisson 分布式锁
- **文件哈希**：SHA-256
- **文件类型检测**：Apache Tika

### 6.2 核心组件
- **FileHandler**：文件处理器接口
- **LocalFileHandler**：本地文件处理器
- **RemoteFileHandler**：远程文件处理器
- **FileCacheManager**：文件缓存管理器
- **TempFileCleaner**：临时文件清理器
- **FileTypeDetector**：文件类型检测器
- **FilePathResolver**：文件路径解析器
- **FileLockService**：文件锁服务

### 6.3 关键流程

#### 6.3.1 本地文件处理流程
1. 接收本地文件路径
2. 验证文件路径的合法性
3. 检查文件是否存在
4. 检查文件大小
5. 检测文件类型
6. 获取文件锁
7. 返回文件信息
8. 释放文件锁

#### 6.3.2 远程文件处理流程
1. 接收远程文件 URL
2. 验证 URL 的合法性
3. 检查缓存是否存在
4. 如果缓存存在且未过期，返回缓存文件
5. 如果缓存不存在或已过期：
   - 创建下载任务
   - 将任务添加到下载队列
   - 下载文件到临时目录
   - 计算文件哈希
   - 保存缓存信息
   - 返回文件信息
6. 释放文件锁

#### 6.3.3 文件缓存清理流程
1. 扫描缓存目录
2. 检查每个缓存文件的过期时间
3. 删除过期的缓存文件
4. 更新数据库中的缓存状态
5. 释放磁盘空间
6. 记录清理日志

## 10. 风险评估

### 10.1 潜在风险
- **磁盘空间不足**：大量临时文件可能导致磁盘空间不足
- **网络问题**：远程文件下载可能因网络问题失败
- **并发冲突**：多个任务同时处理同一文件可能导致冲突
- **缓存失效**：缓存失效可能导致重复下载
- **安全问题**：路径遍历攻击、大文件攻击等安全问题

### 10.2 缓解措施
- **磁盘空间监控**：实时监控磁盘空间，及时清理
- **重试机制**：实现下载失败重试机制
- **文件锁**：使用分布式锁防止并发冲突
- **缓存策略**：实现合理的缓存策略，提高命中率
- **安全验证**：实现路径验证、文件大小限制等安全措施
