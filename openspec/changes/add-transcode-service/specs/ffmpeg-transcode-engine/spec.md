# FFmpeg Transcode Engine 规范

## 1. 概述

本规范定义了基于 FFmpeg 的转码引擎，用于处理视频和音频文件的格式转换、分辨率调整、码率控制等功能。转码引擎是整个转码服务的核心组件，负责执行实际的媒体文件转码操作。

## 2. 功能需求

### 2.1 格式转换
- 支持常见视频格式的转换（MP4、AVI、MKV、MOV、WMV 等）
- 支持常见音频格式的转换（MP3、WAV、AAC、FLAC、OGG 等）
- 支持容器格式的转换（如将 MP4 转换为 MKV）
- 支持编码格式的转换（如将 H.264 转换为 H.265）

### 2.2 视频处理
- 支持分辨率调整（如 1080p、720p、480p 等）
- 支持帧率调整（如 24fps、30fps、60fps 等）
- 支持码率控制（恒定码率 CBR、可变码率 VBR）
- 支持视频裁剪和缩放
- 支持视频滤镜应用（如去噪、锐化、色彩调整等）

### 2.3 音频处理
- 支持采样率调整（如 44.1kHz、48kHz 等）
- 支持比特率调整（如 128kbps、192kbps、320kbps 等）
- 支持声道数调整（单声道、立体声、5.1 环绕声等）
- 支持音频滤镜应用（如降噪、均衡器等）

### 2.4 转码参数控制
- 支持编码器选择（如 x264、x265、VP9、AV1 等）
- 支持编码预设配置（如 ultrafast、fast、medium、slow、veryslow 等）
- 支持 GOP（图像组）大小设置
- 支持 B 帧数量设置
- 支持参考帧数量设置

### 2.5 转码进度跟踪
- 支持实时获取转码进度
- 支持转码速度（如 2.5x 实时速度）
- 支持预计完成时间计算
- 支持转码过程中的错误检测

### 2.6 转码质量控制
- 支持质量参数设置（如 CRF 值）
- 支持质量预设配置
- 支持视觉质量评估
- 支持音频质量评估

## 3. 非功能需求

### 3.1 性能
- 转码速度：至少达到 1x 实时速度（对于 1080p 视频）
- CPU 使用率：合理控制，避免系统过载
- 内存使用率：根据输入文件大小合理分配
- 支持多线程编码

### 3.2 可靠性
- 转码过程中的错误处理
- 支持断点续转（可选）
- 转码结果的一致性保证
- 异常情况下的资源释放

### 3.3 可扩展性
- 支持新增编码器和格式
- 支持自定义转码参数
- 支持插件式架构
- 支持硬件加速（如 GPU 编码）

### 3.4 安全性
- 输入文件的安全性检查
- 避免恶意文件导致的安全问题
- 资源使用限制，防止 DoS 攻击
- 转码过程中的异常处理

## 4. 数据模型

### 4.1 转码任务参数
- **输入文件**：
  - 文件路径
  - 文件格式
  - 视频/音频流信息
  - 文件大小
- **输出配置**：
  - 文件路径
  - 目标格式
  - 视频参数（分辨率、码率、编码器等）
  - 音频参数（采样率、比特率、声道数等）
- **转码选项**：
  - 编码预设
  - 质量参数
  - 滤镜设置
  - 其他高级参数

### 4.2 转码进度信息
- **当前时间**：已处理的时间（秒）
- **总时间**：输入文件的总时间（秒）
- **进度百分比**：0-100
- **转码速度**：实时速度倍数
- **预计完成时间**：秒
- **当前帧**：已处理的帧数
- **总帧数**：总帧数

### 4.3 转码结果
- **输出文件**：
  - 文件路径
  - 文件大小
  - 文件格式
  - 视频/音频流信息
- **转码统计**：
  - 转码耗时
  - 转码速度
  - 质量指标
  - 错误信息（如果有）

## 5. API 接口

### 5.1 转码执行接口
- **路径**：`/api/transcode/engine/execute`
- **方法**：POST
- **请求体**：
  ```json
  {
    "inputFile": "string",
    "outputFile": "string",
    "videoParams": {
      "codec": "string",
      "resolution": "string",
      "bitrate": "string",
      "preset": "string",
      "crf": number
    },
    "audioParams": {
      "codec": "string",
      "sampleRate": number,
      "bitrate": "string",
      "channels": number
    },
    "options": {
      "filters": "string",
      "metadata": {}
    }
  }
  ```
- **响应**：
  ```json
  {
    "transcodeId": "string",
    "status": "PROCESSING",
    "progressUrl": "/api/transcode/engine/progress/{transcodeId}"
  }
  ```

### 5.2 转码进度接口
- **路径**：`/api/transcode/engine/progress/{transcodeId}`
- **方法**：GET
- **响应**：
  ```json
  {
    "transcodeId": "string",
    "progress": 45,
    "currentTime": 22.5,
    "totalTime": 50,
    "speed": 2.5,
    "estimatedTime": 11,
    "status": "PROCESSING"
  }
  ```

### 5.3 转码取消接口
- **路径**：`/api/transcode/engine/cancel/{transcodeId}`
- **方法**：POST
- **响应**：
  ```json
  {
    "transcodeId": "string",
    "status": "CANCELLED",
    "cancelledAt": "timestamp"
  }
  ```

### 5.4 格式支持接口
- **路径**：`/api/transcode/engine/formats`
- **方法**：GET
- **响应**：
  ```json
  {
    "videoFormats": ["mp4", "mkv", "avi", "mov"],
    "audioFormats": ["mp3", "aac", "wav", "flac"],
    "videoCodecs": ["h264", "h265", "vp9", "av1"],
    "audioCodecs": ["aac", "mp3", "opus", "vorbis"]
  }
  ```

## 6. 实现方案

### 6.1 技术选型
- **JavaCV**：核心库，使用其集成的 FFmpeg 库
- **FFmpeg**：通过 JavaCV 集成，无需系统安装
- **ProcessBuilder**：执行 FFmpeg 命令行
- **NIO**：文件 I/O 操作
- **CompletableFuture**：异步处理

### 6.2 核心组件
- **FFmpegExecutor**：FFmpeg 命令执行器
- **TranscodeEngine**：转码引擎核心
- **ProgressTracker**：进度跟踪器
- **FormatDetector**：格式检测器
- **ParameterBuilder**：参数构建器
- **HardwareAccelerator**：硬件加速器（可选）

### 6.3 关键流程

#### 6.3.1 转码准备流程
1. 检测输入文件格式和流信息
2. 验证输出目录权限
3. 构建转码参数
4. 检查 FFmpeg 是否可用
5. 初始化转码环境

#### 6.3.2 转码执行流程
1. 构建 FFmpeg 命令行参数
2. 启动 FFmpeg 进程
3. 捕获标准输出和错误输出
4. 解析输出获取进度信息
5. 实时更新转码进度
6. 处理转码完成或失败

#### 6.3.3 转码完成流程
1. 等待 FFmpeg 进程结束
2. 检查转码结果
3. 验证输出文件
4. 清理临时文件
5. 生成转码报告

## 10. 风险评估

### 10.1 潜在风险
- **输入文件兼容性**：某些特殊格式或损坏的文件可能导致转码失败
- **资源使用过高**：大文件转码可能导致系统资源耗尽
- **转码质量问题**：某些参数组合可能导致输出质量不佳
- **FFmpeg 版本兼容性**：不同版本的 FFmpeg 可能有不同的行为
- **硬件加速依赖**：硬件加速可能在某些环境下不可用

### 10.2 缓解措施
- **输入文件验证**：在转码前检查文件格式和完整性
- **资源限制**：设置 CPU、内存和磁盘使用限制
- **参数验证**：验证转码参数的有效性
- **版本管理**：指定推荐的 FFmpeg 版本
- **降级策略**：硬件加速不可用时自动降级到软件编码
- **错误处理**：完善的错误处理和恢复机制
- **监控告警**：实时监控转码过程，及时发现问题
