# Transcode SSE Progress 规范

## 1. 概述

本规范定义了转码服务的 Server-Sent Events (SSE) 实时进度推送机制，用于将转码任务的进度信息实时推送到前端。SSE 是一种基于 HTTP 的单向服务器推送技术，适合实时更新场景。

## 2. 功能需求

### 2.1 SSE 连接管理
- **连接建立**：客户端建立 SSE 连接
- **连接认证**：验证客户端身份（Cookie 或 API 签名）
- **连接授权**：检查客户端是否有权限接收进度
- **连接限制**：限制每个客户端的连接数
- **连接超时**：设置连接超时时间

### 2.2 进度事件推送
- **任务开始**：推送任务开始事件
- **进度更新**：推送进度更新事件
- **任务完成**：推送任务完成事件
- **任务失败**：推送任务失败事件
- **任务取消**：推送任务取消事件
- **步骤状态**：推送多步骤转码的步骤状态

### 2.3 进度信息
- **任务 ID**：转码任务的唯一标识
- **进度百分比**：转码进度百分比（0-100）
- **转码速度**：转码速度（MB/s）
- **剩余时间**：预计剩余时间（秒）
- **已处理大小**：已处理的数据大小（字节）
- **总大小**：总数据大小（字节）
- **当前步骤**：当前执行的步骤
- **步骤进度**：每个步骤的进度
- **错误信息**：任务失败时的错误信息

### 2.4 心跳机制
- **心跳发送**：定期发送心跳事件
- **心跳间隔**：设置心跳间隔时间
- **心跳超时**：检测客户端是否存活
- **连接保活**：保持连接活跃

### 2.5 断线重连
- **自动重连**：客户端断线后自动重连
- **重连延迟**：设置重连延迟时间
- **重连次数**：限制最大重连次数
- **重连恢复**：重连后恢复进度推送

### 2.6 多任务订阅
- **单任务订阅**：订阅单个任务的进度
- **多任务订阅**：订阅多个任务的进度
- **批量订阅**：批量订阅任务进度
- **取消订阅**：取消任务进度订阅

## 3. 非功能需求

### 3.1 性能
- SSE 连接建立时间：< 1s
- 进度事件推送延迟：< 100ms
- 支持并发连接数：> 1000
- 心跳间隔：30s

### 3.2 可靠性
- 进度推送成功率：> 99%
- 断线重连成功率：> 95%
- 连接保活成功率：> 99%

### 3.3 可扩展性
- 支持水平扩展
- 支持负载均衡
- 支持分布式部署

### 3.4 安全性
- 连接认证和授权（Cookie 或 API 签名）
- 防止未授权访问
- 防止连接滥用

## 4. 数据模型

### 4.1 SSE 事件格式

#### 4.1.1 任务开始事件
```
event: task-started
data: {
  "taskId": "string",
  "strategyId": "string",
  "startTime": "timestamp"
}
```

#### 4.1.2 进度更新事件
```
event: progress-update
data: {
  "taskId": "string",
  "progress": 50,
  "speed": 2.5,
  "remainingTime": 120,
  "processedSize": 512000000,
  "totalSize": 1024000000,
  "currentStep": "transcode",
  "stepProgress": 60
}
```

#### 4.1.3 任务完成事件
```
event: task-completed
data: {
  "taskId": "string",
  "progress": 100,
  "outputFiles": [
    {
      "path": "/path/to/output.mp4",
      "size": 1024000,
      "duration": 300
    }
  ],
  "completedAt": "timestamp"
}
```

#### 4.1.4 任务失败事件
```
event: task-failed
data: {
  "taskId": "string",
  "progress": 45,
  "errorCode": "TRANS_001",
  "errorMessage": "转码失败：FFmpeg 执行错误",
  "failedAt": "timestamp"
}
```

#### 4.1.5 任务取消事件
```
event: task-cancelled
data: {
  "taskId": "string",
  "progress": 30,
  "cancelledAt": "timestamp"
}
```

#### 4.1.6 心跳事件
```
event: heartbeat
data: {
  "timestamp": "timestamp",
  "serverTime": "timestamp"
}
```

### 4.2 Redis 数据结构

#### 4.2.1 SSE 连接
- **名称**：`transcode:sse:connection:{connectionId}`
- **类型**：Redis Hash
- **结构**：
  - `clientId`：客户端 ID
  - `taskId`：任务 ID
  - `connectedAt`：连接时间
  - `lastHeartbeat`：最后心跳时间

#### 4.2.2 客户端连接
- **名称**：`transcode:sse:client:{clientId}`
- **类型**：Redis Set
- **结构**：存储客户端的所有连接 ID

## 5. API 接口

### 5.1 SSE 端点

#### 5.1.1 订阅任务进度
- **路径**：`/api/transcode/progress/{taskId}/sse`
- **方法**：GET
- **参数**：
  - `taskId`：任务 ID
  - `clientId`：客户端 ID（可选）
  - `token`：认证令牌（Cookie 方式）
  - `X-Client-Id`：客户端 ID（API 签名方式）
  - `X-Timestamp`：时间戳（API 签名方式）
  - `X-Signature`：签名（API 签名方式）
- **响应**：SSE 流

#### 5.1.2 批量订阅任务进度
- **路径**：`/api/transcode/progress/sse`
- **方法**：GET
- **参数**：
  - `taskIds`：任务 ID 列表（逗号分隔）
  - `clientId`：客户端 ID（可选）
  - `token`：认证令牌（Cookie 方式）
  - `X-Client-Id`：客户端 ID（API 签名方式）
  - `X-Timestamp`：时间戳（API 签名方式）
  - `X-Signature`：签名（API 签名方式）
- **响应**：SSE 流

## 6. 实现方案

### 6.1 技术选型
- **SSE 服务端**：Spring Web（Spring Boot 4.x，使用 Project Loom 虚拟线程）
- **SSE 客户端**：EventSource API
- **连接管理**：Redis
- **事件发布**：Spring Event / Redis Pub/Sub

### 6.2 核心组件

#### 6.2.1 服务端组件
- **SSEEndpoint**：SSE 端点控制器
- **SSEConnectionManager**：SSE 连接管理器
- **ProgressEventPublisher**：进度事件发布器
- **SSEHeartbeatService**：SSE 心跳服务
- **SSEReconnectHandler**：SSE 重连处理器

#### 6.2.2 客户端组件
- **SSEClient**：SSE 客户端封装
- **SSEReconnectManager**：SSE 重连管理器
- **ProgressEventHandler**：进度事件处理器
- **SSEConnectionMonitor**：SSE 连接监控器

### 6.3 关键流程

#### 6.3.1 SSE 连接建立流程（服务端）
1. 接收客户端 SSE 连接请求
2. 验证客户端身份和权限（Cookie 或 API 签名）
3. 创建 SSE 连接
4. 生成连接 ID
5. 保存连接信息到 Redis
6. 发送连接成功事件
7. 开始发送心跳事件
8. 监听任务进度事件
9. 推送进度事件到客户端

#### 6.3.2 SSE 连接建立流程（客户端）
1. 创建 EventSource 对象
2. 连接到 SSE 端点
3. 监听连接打开事件
4. 监听进度更新事件
5. 监听错误事件
6. 处理进度更新
7. 处理连接断开

#### 6.3.3 进度事件推送流程
1. 转码引擎更新进度
2. 发布进度事件
3. SSE 连接管理器接收事件
4. 查找订阅该任务的连接
5. 推送进度事件到所有订阅的连接
6. 更新连接的最后活动时间

#### 6.3.4 心跳流程
1. 定时器触发
2. 发送心跳事件到所有连接
3. 更新连接的最后心跳时间
4. 检查超时的连接
5. 关闭超时的连接

#### 6.3.5 断线重连流程（客户端）
1. 检测到连接断开
2. 等待重连延迟
3. 重新建立 SSE 连接
4. 恢复进度订阅
5. 请求最新的进度信息
6. 继续接收进度更新

## 10. 风险评估

### 10.1 潜在风险
- **连接泄漏**：连接未正确关闭导致连接泄漏
- **推送延迟**：进度事件推送延迟过高
- **连接断开**：网络问题导致连接频繁断开
- **重连失败**：重连机制失效导致无法恢复连接
- **资源耗尽**：大量连接导致资源耗尽

### 10.2 缓解措施
- **连接监控**：监控连接状态，及时清理异常连接
- **推送优化**：优化推送机制，减少延迟
- **重连机制**：实现可靠的重连机制
- **连接限制**：限制最大连接数，防止资源耗尽
- **资源监控**：监控资源使用情况，及时扩容
