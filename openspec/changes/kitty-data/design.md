## Context

### 背景

当前系统缺少统一的事件上报和统计分析能力，需要构建一个轻量级的事件上报服务 kitty-data。该服务主要用于：

1. **AK/SK 鉴权**：为外部系统提供安全的 API 访问凭证
2. **事件上报**：收集各类业务事件（操作日志、用量统计等）
3. **统计分析**：提供多维度的统计查询和实时监控

### 技术选型

- **配置管理**：viper（支持 YAML 配置、环境变量）
- **日志**：zap（高性能结构化日志）
- **数据库**：MongoDB（适合事件存储和高并发写入）
- **Web 框架**：Gin（轻量、高性能）
- **无 gorm、grpc**：保持轻量化

### 约束

- 不支持 gRPC，仅支持 HTTP API
- 不使用 ORM，使用原生 MongoDB Driver
- 鉴权逻辑必须高性能（本地缓存）
- **API 风格**：标准 RESTful，返回值无通用 DTO 包装（无 Result/Response 泛型包装器）

---

## Goals / Non-Goals

### Goals

1. **AK/SK 鉴权系统**
   - 高性能本地缓存鉴权
   - 定时同步最新 AK/SK 数据
   - 支持手动刷新缓存

2. **签名鉴权中间件**
   - 基于 HMAC-SHA256 签名验证
   - 防重放攻击（时间戳校验）
   - 可配置时间戳容忍范围

3. **事件上报**
   - 记录事件类型、操作者、操作值
   - 支持高并发写入

4. **统计分析**
   - 多维度统计（时间、事件类型、操作者）
   - 排名查询
   - 趋势分析

5. **实时监控**
   - SSE 流式监控

### Non-Goals

- 不支持 gRPC 通信
- 不支持数据库事务（事件上报追求性能）
- 不支持复杂的权限控制（仅 AK/SK 级别）
- 不支持事件溯源（仅支持聚合统计）

## Decisions

### 1. AK/SK 本地缓存设计

**方案**：应用启动时启动定时任务，定时拉取 AK/SK 全量数据到内存 Map

**决策理由**：
- MongoDB 查询性能有限，鉴权需要毫秒级响应
- AK/SK 数据量小（全量加载到内存开销可控）
- 定时刷新保证数据一致性

**备选方案**：
- 每次请求查询 MongoDB → 性能太差，否决
- 使用 Redis 缓存 → 增加系统复杂度，当前场景不需要

### 2. 签名算法设计

**方案**：HMAC-SHA256(secretKey, ak + timestamp)

**决策理由**：
- 业界通用方案，安全性高
- 计算性能好
- 实现简单

**备选方案**：
- RSA 签名 → 性能差，否决
- MD5 → 安全性不足，否决

### 3. 时间戳校验

**方案**：允许正负 N 秒的容忍范围（N 可配置）

**决策理由**：
- 客户端时钟不同步是常见问题
- 正负范围比仅允许未来或仅允许过去更合理
- 配置化便于调整

### 4. 事件存储设计

**方案**：按时间分片的事件集合

**决策理由**：
- 事件数据量大，按时间分片利于查询和清理
- MongoDB 原生支持 TTL 索引，可自动清理历史数据

**备选方案**：
- 单集合 + 索引 → 数据量大后性能下降
- 分库分表 → 过度设计

### 5. 统计查询设计

**方案**：MongoDB 聚合管道（Aggregation Pipeline）

**决策理由**：
- 支持复杂统计查询
- 性能优于多次查询 + 代码计算
- 易于维护

**备选方案**：
- 预计算 + 缓存 → 实现复杂，不适合多变查询
- 应用层聚合 → 内存开销大

## Risks / Trade-offs

### 1. AK/SK 缓存一致性

**风险**：定时任务刷新期间，可能存在短暂的不一致

**缓解**：
- 刷新使用原子操作替换整个 Map
- 读取操作无锁（读 Map 本身线程安全）
- 提供手动刷新接口用于紧急情况

### 2. 时间戳校验窗口

**风险**：过大的窗口增加重放攻击风险

**缓解**：
- 默认窗口较小（5 分钟）
- 生产环境建议 1-3 分钟

### 3. MongoDB 连接池

**风险**：高并发写入时连接耗尽

**缓解**：
- 合理配置连接池大小
- 使用批量写入优化

### 4. SSE 长期连接

**风险**：大量 SSE 连接占用资源

**缓解**：
- 限制单个连接的订阅条件
- 实现连接超时和心跳机制

## Migration Plan

### 步骤

1. **创建项目结构**
   - 初始化 Go Module
   - 配置目录结构

2. **实现核心功能**

3. **实现 AK/SK 鉴权**
   - 数据模型定义
   - 缓存服务
   - 定时任务

4. **实现签名中间件**
   - 签名验证逻辑
   - Gin 中间件

5. **实现事件上报**
   - API 接口
   - MongoDB 写入

6. **实现统计分析**
   - 聚合查询
   - SSE 监控

### 回滚方案

由于是新服务，回滚直接停止服务即可，不影响现有系统。
