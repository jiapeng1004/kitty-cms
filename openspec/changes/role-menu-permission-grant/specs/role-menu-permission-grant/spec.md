## ADDED Requirements

### Requirement: 角色可通过接口开通菜单及关联权限
系统必须提供接口，使管理员能够为指定角色开通某个菜单，并根据菜单声明的权限 code（`p_codes`）及管理员在页面上的勾选结果，为角色同步开通对应权限。

#### Scenario: 使用主接口为角色开通菜单与选中权限
- **WHEN** 管理员在角色管理页面选择某个角色和菜单，看到该菜单声明的权限列表（来源于菜单的 `p_codes`），保持默认全选或取消部分勾选，并提交请求到主接口，携带 `roleId`、`menuId` 以及最终选中的权限 code 列表
- **THEN** 系统在 `kt_role_menu` 中创建或更新该角色与该菜单的绑定关系，并在 `kt_role_permission` 中为该角色补写所有勾选的权限 code 对应的角色-权限关系（仅对还不存在的关系做插入）

#### Scenario: 使用 Super 接口自动为角色开通菜单及全部声明权限
- **WHEN** 运维或超级管理员调用 Super 接口，为某个角色开通指定菜单，且未在请求中显式传入权限 code 列表
- **THEN** 系统在 `kt_role_menu` 中创建或更新该角色与该菜单的绑定关系，并自动读取该菜单在 `kt_menu.p_codes` 中声明的全部权限 code，为该角色在 `kt_role_permission` 中补写所有这些权限 code 对应的角色-权限关系（仅对还不存在的关系做插入）

### Requirement: 主接口必须校验前端传入的权限 code 合法性
主接口在处理前端回传的权限 code 列表时，必须保证这些 code 全部属于该菜单在 `kt_menu.p_codes` 中声明的集合，任何不合法的 code 都必须导致请求失败。

#### Scenario: 前端传入权限 code 全部合法
- **WHEN** 管理员在页面勾选的权限 code 列表是菜单 `p_codes` 声明集合的真子集或全集，并提交到主接口
- **THEN** 系统校验通过，请求继续执行，并为角色开通这些权限 code

#### Scenario: 前端传入包含未在菜单中声明的权限 code
- **WHEN** 前端提交的权限 code 列表中包含不在该菜单 `p_codes` 声明集合内的任意 code
- **THEN** 系统必须拒绝本次请求，不对 `kt_role_menu` 和 `kt_role_permission` 做任何修改，并返回明确的业务错误（例如「权限 code 非法」）

### Requirement: 支持菜单声明的必选权限校验
系统必须支持菜单声明部分权限为必选权限的能力，并在主接口中针对必选权限进行校验，防止管理员在页面上误取消这些关键权限。

#### Scenario: 管理员提交的权限 code 覆盖全部必选权限
- **WHEN** 菜单配置中存在必选权限集合（如通过专门字段或标记配置），且管理员在页面上提交的权限 code 列表包含所有必选权限
- **THEN** 系统在完成「子集校验」的基础上，还应判定必选权限校验通过，请求可继续执行

#### Scenario: 管理员取消了部分必选权限
- **WHEN** 菜单配置中存在必选权限集合，而管理员在页面上取消了其中部分必选权限，导致提交的权限 code 列表不再包含全部必选权限
- **THEN** 系统必须拒绝本次请求，不对 `kt_role_menu` 和 `kt_role_permission` 做任何修改，并返回明确的业务错误（例如「必选权限缺失」）

### Requirement: 角色-菜单及角色-权限关系写入需具备幂等性
系统在为角色开通菜单及权限时，必须保证重复调用接口不会产生重复的绑定记录或报错，应以「存在则忽略、缺失则补写」的方式实现幂等。

#### Scenario: 重复为同一角色和菜单调用开通接口
- **WHEN** 调用主接口或 Super 接口多次，为同一角色和同一菜单执行开通操作
- **THEN** 系统在 `kt_role_menu` 中最多只保留一条该角色与该菜单的绑定记录，且在 `kt_role_permission` 中不会产生重复的角色-权限记录；对于已存在的关系系统应直接跳过，仅为缺失的权限关系做补写

#### Scenario: 更新菜单声明的权限后再次调用开通接口
- **WHEN** 菜单的 `p_codes` 配置被更新（增加或减少某些权限），随后再次通过 Super 接口或主接口为角色开通该菜单
- **THEN** 系统在补写权限时，只会为新增的、且尚未存在于 `kt_role_permission` 的权限 code 创建新关系；对已存在或被移除的权限按当前业务规则处理（例如：不自动删除已存在的旧权限）
