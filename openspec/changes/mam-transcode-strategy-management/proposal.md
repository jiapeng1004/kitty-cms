## Why

MAM 需要可运营的转码策略体系与一致的上传/预览/下载体验：策略需可配置、可绑定栏目、可与底层转码服务解耦；上传时需按明确优先级选用策略或降级为「不转码入库」；视频需在转码周期内具备可用封面与后续雪碧图能力；资源对外统一开放展示，列表与详情直接携带预览与码率信息，避免单独预览接口；下载需按码率分级并纳入行为上报；检索需事务后与 ES 可靠异步一致。本变更将上述能力以前后端一体的方式纳入 OpenSpec，便于评审与分阶段实现。

## What Changes

- **转码策略数据与后台管理**：新增/完善转码策略 CRUD 与前台配置能力；策略支持标记为「全局默认」，且 **视频类全局默认至多一条**、**音频类全局默认至多一条**（按资源类型维度约束，实现上需唯一性校验或等价约束）。
- **栏目与策略绑定**：栏目可绑定转码策略表中的一条记录（建议按资源类型维度绑定，与下文解析链一致）；绑定关系在管理端可维护。
- **上传时策略解析链**：资源上传创建转码流程时，按顺序解析生效策略：
  1. 若上传请求 **显式指定** 转码策略（或策略类标识），则使用该指定策略；
  2. 否则若栏目对 **当前资源类型** 存在绑定策略，则使用栏目绑定策略；
  3. 否则若存在 **该资源类型** 的全局默认策略，则使用全局默认；
  4. 若以上均未命中，则 **不发起转码**，资源按源码/既定规则 **直接入库**（与现有落库与存储模型对齐）。
- **策略与底层转码服务映射**：每条转码策略 **必须** 可配置底层实际转码服务使用的 **策略 ID**（或等价外部标识）；**可选** 配置底层服务依赖参数的 **JSON 字符串**（透传或经校验后下发给转码引擎），用于对接 kitty-transcoder 或后续多引擎。
- **视频固定任务**：视频资源上传后 **固定发起同步抽封面** 任务，保证转码进行期间前端列表/卡片仍能展示封面；视频在封面任务之后 **默认再发起异步抽雪碧图** 任务（与转码主链路解耦，失败可重试，不改变「默认发起」语义）。
- **资源开放与预览链接**：当前阶段产生的资源 **访问策略统一为 open**（无需按资源做封闭预览权限分支）；**不新增** 专用「后端预览接口」；**资源列表分页接口** 在每条记录中返回 **适合该资源类型的预览链接**（如封面图 URL、音频波形或占位策略等与现有前端约定一致）；**资源详情** 与 **码率列表** 相关接口直接返回 **该资源已有的全部码率/衍生产物** 信息，供详情页与码率列表页一次性展示。
- **下载与行为上报**：
  - **单个下载**：用户选择码率分级后，返回 **可直接下载的链接**（签名 URL 或直接地址，与存储抽象一致）；下载意图通过 **行为上报接口** 上报：**资源 id**、**码率 destinationType**（或统一码率分级标识）、**资源标题**、**操作人 id**。
  - **批量下载**：用户选择 **码率分级**；对 **不具备该码率产物** 的素材，前端 **弹窗** 询问是否 **从批量中排除**；对 **未排除且未命中所选码率分级** 的项，**降级为下载源码链接**；批量完成后通过 **批量行为接口** 上报各资源 **实际下载所采用的码率**（含源码降级情况需可区分）。
- **ES 同步**：资源 **主数据落库事务提交成功后**，**固定** 投递 **Kafka** 消息；由 **MAM 自身消费** 该主题，**异步** 将变更同步至 Elasticsearch（与现有 `material-search-sync` 方向一致，本变更明确 Kafka 为投递通道与自监听职责）。

## Capabilities

### New Capabilities

- `mam-transcode-strategy-config`: 转码策略配置模型、全局默认约束（视频/音频各至多一条全局默认）、底层策略 ID 与可选 JSON 参数字段；管理端 API 与前端策略管理页。
- `mam-catalog-transcode-binding`: 栏目与转码策略绑定（按资源类型或统一策略引用，与解析链一致）；栏目编辑/详情展示绑定关系。
- `mam-upload-strategy-resolution`: 上传时策略解析顺序（显式指定 → 栏目绑定 → 全局默认 → 不转码入库）及与转码任务创建的衔接。
- `mam-transcode-main-task-handoff`: 解析结果到主转码任务的交付边界（`engineStrategyId` / `extraParamsJson` 透传、未命中主转码时不创建主链路任务、显式来源可审计）。
- `mam-video-cover-sprite-tasks`: 视频同步抽封面、默认异步抽雪碧图的任务编排与与转码主任务的关系。
- `mam-resource-open-preview-fields`: 列表/详情/码率列表字段契约：预览链接内嵌、全量码率返回；无单独预览接口。
- `mam-resource-download-bitrate`: 单文件与批量下载的码率选择、缺码率时的交互与源码降级；行为上报与批量行为上报字段契约。
- `mam-resource-kafka-es-sync`: 事务后 Kafka 投递、MAM 自消费异步写 ES 的边界与幂等/重试原则（在设计阶段细化）。
- `mam-transcode-delivery-sync`: 前后端**同迭代**交付、**契约基线**、垂直切片**联合验收**；联调环境共享；**Cursor MCP `chrome-browser`** 作为**约定**的浏览器端回归方式之一（与项目 `.cursor/mcp.json` 一致，并允许手写 E2E 补位）。

### Modified Capabilities

- `material-transcode-strategy`（若已并入主 spec）：扩展为包含全局默认唯一性、底层策略 ID、JSON 参数、栏目绑定与上传解析链的完整需求（本变更实施后通过 `openspec sync` 合并 delta）。
- `material-search-sync`：补充「事务后 Kafka + 自监听」的投递与消费职责说明（与现有队列抽象并存时在设计中定夺单一事实来源）。

## Impact

- **后端**：MAM/material 领域服务、转码任务编排、栏目与策略存储、上传入口、资源查询 DTO、下载链接签发、Kafka 生产者与消费者、ES 同步消费者、行为上报接口对接（kitty-data 或既有事件服务）。
- **前端**：转码策略管理页、栏目绑定策略、资源列表/详情/码率列表展示字段适配、下载与批量下载交互、行为上报调用；与后端按 **垂直切片同迭代** 开发，**共享 exchange 契约**；联调时启用 **MCP 浏览器**（`chrome-browser`，见根目录 `.cursor/mcp.json`）做关键路径**浏览器侧**回归，与自动化/契约测试**互补**。
- **数据**：转码策略表、栏目策略绑定表（或扩展栏目表）、必要时迁移脚本；全局默认约束依赖唯一索引或应用层校验。
- **基础设施**：Kafka 主题与消费组、ES 索引字段若因码率/预览链接展示需扩展则在 design 中列出。
- **兼容性**：新增字段与接口为主；若已有预览接口调用方存在，需在前端切换为列表/详情内嵌链接后废弃调用（本提案阶段标记为迁移项）。
