## ADDED Requirements

### Requirement: 转码策略必须可持久化并绑定底层引擎标识
系统 MUST 提供转码策略的创建、查询、更新与（按业务规则）删除能力；每条策略记录 MUST 包含对底层转码服务有效的 **引擎策略 ID**（`engineStrategyId` 或项目内统一命名），并 SHOULD 提供人类可读名称与 **资源类型** 维度，以便与全局默认及栏目绑定一致。

#### Scenario: 新建策略并填写引擎策略 ID
- **WHEN** 管理员在策略管理页提交新策略，填写名称、资源类型、引擎策略 ID 及可选 JSON 参数字符串
- **THEN** 系统持久化该记录并可在策略列表中查询到；后续上传解析链与任务编排可使用该 `engineStrategyId` 向 kitty-transcoder（或配置的其他引擎）发起转码

#### Scenario: 仅允许合法 JSON 或约定格式的可选参数
- **WHEN** 若项目对 `extraParamsJson` 启用校验策略（Schema 或白名单）
- **THEN** 非法内容请求 MUST 失败并返回可理解的校验错误，且不写入或部分写入非法字段

### Requirement: 按资源类型的全局默认策略至多各一条
对每一种参与策略解析的 `resourceType`（至少包含**视频**与**音频**），系统 MUST 保证标记为 **全局默认**（`isGlobalDefault=true`）的策略**至多存在一条**；任何会导致违反该不变量的创建或更新操作 MUST 被拒绝。

#### Scenario: 为视频再设一条全局默认
- **WHEN** 已存在一条 `resourceType=视频` 且为全局默认的策略，管理员再创建或把另一条同类型策略设为全局默认
- **THEN** 系统必须拒绝并提示「该资源类型已存在全局默认策略」或等价语义，且数据库中仍只保留原有一条全局默认

#### Scenario: 将现有全局默认改为非默认后设新默认
- **WHEN** 管理员先将原视频全局默认取消，再为另一条视频策略勾选全局默认
- **THEN** 系统通过校验，新策略成为该类型唯一全局默认，且列表与后续解析链均反映该变更

### Requirement: 管理端必须能维护策略全生命周期
系统 SHALL 在管理端提供转码策略管理界面（或等价入口），支持列表、详情、创建、编辑，以及受控删除（若存在栏目绑定或历史任务引用，行为 SHALL 在实现中明确定义为禁止删除或级联规则）。

#### Scenario: 运营修改引擎策略 ID 以切换底层模板
- **WHEN** 管理员编辑某条策略，仅将 `engineStrategyId` 更新为新模板 ID
- **THEN** 新上传且命中该策略的任务 MUST 使用新 ID；已创建任务是否重跑由产品策略决定，但不得静默篡改已完成任务历史事实

### Requirement: 策略管理接口必须受权限与租户边界约束
对转码策略的**创建/查询/更新/删除**等管理 API，系统 MUST 执行与现有后台一致的**身份认证**与**授权**（角色、菜单、权限点或等价机制）；**不得**在匿名下修改全局默认或引擎参数。多租户或应用实例若存在，策略数据 **MUST** 落在正确的租户/实例隔离边界内，与 `catalog_transcode_strategy_binding` 的栏目范围一致。

#### Scenario: 无权限用户无法修改全局默认
- **WHEN** 已登录用户**不具备**转码策略管理所需权限
- **THEN** 任何创建、更新、删除、切换全局默认的请求 MUST 返回 **403** 或项目约定的**无权限**业务码，**不得**落库

#### Scenario: 策略列表支持分页与按类型过滤
- **WHEN** 管理端拉取策略列表
- **THEN** 接口 SHOULD 支持**分页**与按 `resourceType`、名称等**过滤**（与列表页性能一致）；全部命中项 **MUST** 满足当前调用者的可见范围
