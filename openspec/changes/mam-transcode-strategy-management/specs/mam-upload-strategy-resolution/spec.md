## ADDED Requirements

### Requirement: 上传时必须按固定顺序解析转码策略
在创建主转码任务前，系统 MUST 按以下**严格顺序**解析**一条**将用于主转码的策略（或判定不转码）；**先命中先使用**，后续步骤不再参与：

1. 上传请求**显式指定**了策略（或经约定的策略类参数），且经校验**存在、可用且与当前资源类型匹配** → 使用该策略。
2. 否则，若**当前资源类型**在**当前目标栏目**上存在绑定策略 → 使用栏目绑定策略。
3. 否则，若该资源类型存在**全局默认**策略 → 使用全局默认。
4. 否则 **不创建主转码任务**，资源按业务规则**源码/既定方式入库**。

#### Scenario: 显式指定策略覆盖栏目与全局
- **WHEN** 上传请求携带有效显式策略标识，且该策略适用于当前资源类型
- **THEN** 系统 MUST 使用该显式策略创建主转码任务（若该类型会发起主转码），**不得**因栏目或全局默认证存在而改用其他策略

#### Scenario: 无显式、有栏目绑定时用栏目
- **WHEN** 上传无显式策略，但栏目对当前资源类型有绑定
- **THEN** 系统 MUST 使用栏目绑定策略作为后续主转码策略来源

#### Scenario: 无显式、无栏目绑定时用全局默认
- **WHEN** 无显式策略且该类型在栏目上无绑定，但该类型存在全局默认
- **THEN** 系统 MUST 使用全局默认作为后续主转码策略来源

#### Scenario: 均未命中时源码入库不主转码
- **WHEN** 无显式、无栏目绑定、无全局默认（或该类型不配置转码入口）
- **THEN** 系统 MUST **不**创建主转码任务，资源仍依现有模型完成元数据与文件入库，且后续解析链不自动补跑主转码

### Requirement: 显式策略非法时必须失败或可预测降级
当上传**携带**了显式策略但校验失败（不存在、类型不符、无权限等）时，系统 MUST **拒绝本次上传/创建**或按产品在实现前锁定的**唯一**降级策略（若采用降级，须在接口文档中明确且本变更默认 **不降级** 为隐式链）。

#### Scenario: 显式策略 ID 不存在
- **WHEN** 请求包含策略标识但该策略不存在
- **THEN** 请求失败并返回明确错误，且不得静默改用栏目或全局默认，除非该接口在发布说明中明确声明「回退到隐式链」

### Requirement: 资源类型必须由受信来源确定
解析链中「**当前资源类型**」**MUST** 来自**上传与资源元数据**的受信输入（文件魔数/ MIME、用户选择、编目规则等经产品定义的组合），**不得**仅信任可伪造的客户端随意字符串；若无法确定类型，**MUST** 走明确失败或**按项目默认**的**安全**类型判定（在实现说明中写清）。

#### Scenario: 类型与显式策略不一致
- **WHEN** 显式指定的策略其 `resourceType` 与解析出的资源类型不一致
- **THEN** 请求 **MUST** 失败并提示类型与策略不匹配

### Requirement: 显式策略参数在分片与合并场景下语义一致
若上传支持**分片**、**断点续传**或**多次完成回调**，显式策略标识 **MUST** 在**首次**与**最终**完成请求间**一致**或**以最终可文档化的一源为准**；**不得**出现首包带 A、尾包改 B 而无版本控制**静默**生效。若禁止变更，尾包若与首包不一致 **MUST** 失败。

#### Scenario: 分片上传仅首包带策略
- **WHEN** 产品约定「仅第一次 init 请求可带 `strategyId`」
- **THEN** 后续分片**不得**覆盖；若后续分片携带冲突值，**MUST** 拒绝或忽略（以 API 文档**唯一**声明为准）
