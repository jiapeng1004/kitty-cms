## ADDED Requirements

### Requirement: 接口契约必须与前后端同迭代评审并基线化
在实现本变更相关功能时，**exchange/OpenAPI/错误码表** 的**首版** **MUST** 在**同一迭代**内经前后端**共同评审**后冻结为**基线**；后续字段增删**MUST** 可追踪（PR、变更单或 `exchange` 版本注释）。**禁止**仅后端在分支内改契约而前端在另一套文档上开发超过一个迭代。

#### Scenario: 策略 CRUD 首版可对接
- **WHEN** 后端开始实现 `transcode_strategy` 管理接口
- **THEN** 同迭代内**已存在**可供前端引用的**正式** DTO/路径/业务码定义（以仓库中 `exchange` 或导出的 API 说明为准），且前端可据此**并行**实现页面骨架与表单校验

#### Scenario: 契约变更需双向知会
- **WHEN** 必须修改已冻结的请求/响应或错误码
- **THEN** 变更**MUST** 在合并前**同步**到前端可消费的契约载体，**不得**在联调日「口头告知」为唯一来源

### Requirement: 功能交付须按垂直切片组织且切片内需前后端可演示
本变更的落地 **SHOULD** 按 **垂直切片**（如：策略管理 → 栏目绑定 → 上传与解析 → 列表/详情 → 下载与行为上报 → 检索与 Kafka/ES）组织；**每一切片在标记完成前** **MUST** 满足：**后端接口可用** 且 **前端页面或等价调用方可演示同一路径**（可最小可用），**或** 经产品书面同意**仅半端**先合（**例外**须记录）。

#### Scenario: 策略管理切片完成标准
- **WHEN** 将「转码策略管理」切片记为可测/可合并
- **THEN** 管理 API 在联调环境可调用，且管理端**至少**能完成列表+创建+全局默认互斥的**可演示**流程（**或** 与契约一致的 Storybook/临时页**明确**在团队约定内）

### Requirement: 联调环境须前后端可共享访问
**联调/预发** 环境（或**本地**通过统一网关的等价约定）**MUST** 对前后端**双方**可访问，且包含**鉴权、存储、转码依赖** 中在契约占位的部分（真实或经批准的 mock）；**MUST** 有书面或 Wiki 的**联调说明**（Base URL、测试账号、特征开关、已知缺陷）。

#### Scenario: 新成员可独立联调
- **WHEN** 新同学按文档配置前后端
- **THEN** 能在**一小时内**跑通**至少一条** 本变更相关的完整路径（**或** 明确列出阻塞项与 owner）

### Requirement: MCP 浏览器联调为约定验收方式之一
团队 **SHALL** 在联调/发布前，使用 **Cursor 配置的 Chrome 浏览器类 MCP**（见仓库 **`.cursor/mcp.json`** 中 `chrome-browser` 的 `url`，默认指向 `http://localhost:12306/mcp`）对**关键用户路径**做**可重复**的**浏览器端**验证，**前提**为**本机/CI** 已按项目说明启动**兼容**的 MCP 浏览器服务；若该服务**未**在环境中启用，**MUST** 以**等价的**人工浏览器回归清单**补位**，**不得**「无 E2E 则直接上线」本变更的 UI 面。

#### Scenario: MCP 服务可用时的验证范围
- **WHEN** Chrome MCP 可连接
- **THEN** 联调可覆盖：登录管理端、策略列表/创建、栏目绑定、资源列表/详情字段展示、触发展示下载请求（在许可环境下）

#### Scenario: MCP 不可用时
- **WHEN** 本地 12306 或配置的 MCP 服务未启动
- **THEN** 责任人在合并说明中**注明**已执行**手写** E2E 检查表或另一套 E2E 自动化，**且** 契约测试仍通过
