## ADDED Requirements

### Requirement: 资源访问策略在现阶段统一为开放
本阶段系统 SHALL 将本变更所涉资源的对外访问/展示策略视为 **open**；不在接口层为「封闭预览」单独增加分支。若未来引入封闭预览，须另立变更与策略字段。

#### Scenario: 列表与详情不区分封闭预览
- **WHEN** 客户端请求资源分页列表或资源详情
- **THEN** 返回体中的预览与码率类字段在符合权限模型前提下**统一返回**（在 open 阶段即全部具备可见性的资源），不依赖单独预览 API

### Requirement: 不得新增专用「后端预览接口」
系统 MUST **不**为「获取预览」而新增**独立**的 HTTP 接口；预览所依赖的 URL 或同等级信息 **MUST** 由**资源列表分页**、**资源详情**及**码率/衍生产物**相关响应**直接内嵌**。

#### Scenario: 前端不调用单独预览端点
- **WHEN** 前端需要展示某资源的封面或音频等预览能力
- **THEN** 前端**仅**从列表或详情的内嵌字段读取（或从既有存储直链与项目约定派生），**不**需调用新预览专用端点

### Requirement: 分页列表必须内嵌与类型匹配的预览信息
**资源列表分页**接口的每条记录 MUST 包含**适合该资源类型**的预览信息（如视频封面图 URL、音频 waveform 或占位符策略等与现有产品约定一致），并反映**当前已就绪**状态（未就绪时字段可为空或显式缺省，行为与前端约定一致但须在 API 文档中写清）。

#### Scenario: 视频在列表中展示封面 URL
- **WHEN** 列表中存在视频类资源且封面已就绪
- **THEN** 该条 DTO 中 MUST 带可供 `<img>` 或等价组件直接使用的封面 URL 或等效内嵌

### Requirement: 资源详情与码率列表须一次性返回全量已就绪码率与产物
**资源详情**与**码率/衍生产物**相关接口 MUST 返回该资源在存储与任务中**已存在的全部码率/产物**元数据（如清晰度 label、`destinationType`、文件大小、时长等，以产品字段为准），以支撑详情页与码率选择器**不依赖**额外汇总请求，除非因性能在后续变更中明确定义**分页/懒加载**。

#### Scenario: 多码率就绪时详情含全部
- **WHEN** 某视频已有多种码率输出
- **THEN** 资源详情或专用码率列表接口的一次响应**包含**全部已就绪项，前端的码率列表页**无需**再为汇总码率而调用其它专用接口

### Requirement: 新增字段应对旧客户端保持向后兼容
列表与详情上为预览/码率新增的 JSON 字段 **SHOULD** 为**可选**或带**合理默认**，使未改动的旧版客户端**不因**未知字段而崩溃；若必须引入**必填**新字段，**MUST** 在版本策略（API 版本号或**协商头**）中说明，或保证网关/序列化层对旧端兼容。

#### Scenario: 旧版 App 拉取新列表
- **WHEN** 旧版客户端只解析历史字段
- **THEN** 响应**不会**因新增 `coverUrl` 等**额外**键而导致解析失败（以实际栈为准；**不得**在文档中要求客户端**必须**忽略未知键才能工作，除非为已知局限）

### Requirement: 开放展示不等于无鉴权
即使本阶段**统一 open** 的**展示**语义，列表与详情 **MUST** 仍经过既有**资源可见性**与**用户上下文**（登录、栏目权限等）检查；`open` **不**表示**匿名**可拉取**全部**资源元数据。具体与 `material-catalog-permission` 等既有规范对齐。

#### Scenario: 无栏目读权限
- **WHEN** 用户不可见某资源所在栏目
- **THEN** 该资源**不得**出现在其列表结果中，详情**不得**直接返回 200+ 全文（**除非**有分享令牌等**另有** spec）
