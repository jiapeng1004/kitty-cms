## ADDED Requirements

### Requirement: 视频必须固定发起同步抽封面任务
对于**视频**类资源，系统 MUST 在资源/上传主流程中**始终**安排**抽封面**任务，使其在**用户可感知的较短时间**内（相对主转码完成）产生封面，以保障**转码进行期间**列表/卡片等场景仍可展示封面。封面任务**独立于**主转码策略是否被命中：即使未发起主转码，仍应抽封面，除非产品定义某类「纯视频」例外（本变更默认**无例外**）。

#### Scenario: 有主转码时列表仍有封面
- **WHEN** 视频主转码长时间进行中
- **THEN** 已完成的抽封面结果 MUST 可被列表/详情接口用于展示，无需等待主转码结束

#### Scenario: 无主转码时仍抽封面
- **WHEN** 按解析链**未**创建主转码任务，但资源为**视频**且可解析出可抽帧的源
- **THEN** 系统仍 MUST 安排并完成抽封面（失败走任务失败与重试策略）

### Requirement: 视频在封面之后默认再发起异步雪碧图任务
在抽封面任务**成功完成**后，系统 MUST **默认**再投递**异步**抽**雪碧图**任务；雪碧图任务**与主转码解耦**（独立任务类型/队列），**失败可重试**，且**不**因雪碧图失败而自动将主转码判为失败（除非产品另行规定）。

#### Scenario: 雪碧图失败可重试且不影响主转码成功语义
- **WHEN** 主转码与封面均已成功，雪碧图任务失败
- **THEN** 系统记录失败并允许重试；主转码成功状态**保持不变**（与默认语义一致）

#### Scenario: 默认发起不保证首次即成功
- **WHEN** 封面刚完成
- **THEN** 系统 MUST 已登记或投递雪碧图任务（「默认发起」的语义是**可观测的调度**，而非**首次执行必成**）

### Requirement: 封面、雪碧图与主转码任务类型必须可区分
系统 MUST 将**主转码**、**抽封面**、**抽雪碧图**以**不同**任务类型或**可区分**的状态机记录，以便独立重试、独立统计，**不得**混为同一状态位导致无法判断「封面已好、主转码仍跑」。

#### Scenario: 列表只依赖封面就绪
- **WHEN** 主转码仍在进行，但封面任务已完成
- **THEN** 列表接口**可以**根据封面字段展示缩略图，**不得**因主转码未完成而**隐藏**已就绪封面（与 `mam-resource-open-preview-fields` 一致）

### Requirement: 封面未就绪时列表字段行为可预期
在封面任务**未**成功前，列表/详情中封面相关字段 **MAY** 为空、占位图 URL 或「处理中」枚举；**MUST** 在 API 文档中规定**一种**约定，**不得**在不同端返回互斥含义的混用状态字。

#### Scenario: 封面失败可重试
- **WHEN** 抽封面任务失败
- **THEN** 系统 SHOULD 支持按既有任务中心策略**重试**；主转码与雪碧图任务**独立**于该重试决策（除非资源已删除）
