## ADDED Requirements

### Requirement: 主转码任务必须携带已解析策略的引擎侧标识与可选参数
当上传解析链**命中**一条转码策略并**需**创建**主转码**任务时，系统 MUST 在持久化的主转码任务记录中保存该策略的 **`engineStrategyId`**，并 MUST 将对底层转码服务（如 kitty-transcoder）的入参**绑定**为**同一条**策略所对应的标识；若策略含 **`extraParamsJson`**，MUST 按与引擎的集成契约**原样或经校验后**随任务/请求一并传递，**不得**在调用链上丢失或替换为无来源的硬编码，除非经显式、已校验的上传端覆盖项（且须在接口文档中声明优先级）。

#### Scenario: 成功解析策略后创建主转码任务
- **WHEN** 解析链返回策略 S，且本资源需发起主转码
- **THEN** 对转码服务发起的任务创建**必须**使用 S 的 `engineStrategyId`；且任务存储中**可**追溯到 `strategyId` 或等效外键，便于排障

#### Scenario: 策略含 JSON 时引擎收到一致参数
- **WHEN** 策略 S 的 `extraParamsJson` 非空
- **THEN** 引擎实际收到的**有效载荷**与库中 S 的语义**一致**（在允许的校验/规范化之后）；若因引擎拒绝而失败，**不得**在不经更新策略的情况下**静默改参**重试，除非为幂等可重复的同参重试

### Requirement: 未命中主转码时不得创建主转码挂接记录
- **WHEN** 解析链未命中主转码（进入「不转码、源码入库」路径）
- **THEN** 系统 **MUST NOT** 为「主转码」目的创建**挂接 kitty-transcoder 主模板**的转码任务；**视频**的封面/雪碧图等**独立**任务类型**不受**本否定约束（见 `mam-video-cover-sprite-tasks`）

#### Scenario: 无全局无栏目无显式为无主转码
- **WHEN** 非视频或视频但解析链不发起主转码
- **THEN** 主转码任务表**无**对应**进行中/待处理**的主链路记录（若存在历史重试/残留则属异常，**不在**本规范内定义除虫策略，但实现 SHOULD 自洽）

### Requirement: 显式策略与已解析结果必须可审计关联
- **WHEN** 上传显式指定策略并成功创建主转码任务
- **THEN** 系统 SHOULD 在任务或资源扩展字段中保留**显式**来源（如 `source=EXPLICIT`）与 `strategyId`，以便审计与对账

#### Scenario: 与栏目默认区分
- **WHEN** 同一次上传统计「为何使用该策略」
- **THEN** 区分显式/栏目/全局 三类**至少**在**日志或持久化**其一可复现，以便运营与排障
